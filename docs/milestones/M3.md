## Plan (as executed)

1. Decision core, input manager, gateway and actuator as allocation-free C++17 with gtests
   named after the SPEC ctest selectors (already on `main` before this report).
2. Arbiter process `guara_rta_node`: `ModeBase` owned mode + `ModeExecutorBase`, asynchronous
   `VEHICLE_CMD_SET_NAV_STATE` on `fmu/in/vehicle_command_mode_executor` (avoids `sendCommandSync` [G A.1]).
3. Geofence channel adapter wired into the tick (ADR 0004); disabled unless parameterized.
4. AC-20 grep: no `deferFailsafesSync(true)`.
5. SITL: user `SET_NAV_STATE` (FM-8), `kill -9` of the arbiter in CF (FM-1) and Hold (FM-2),
   armed restart (FM-3), hang injection (FM-4/FM-5), and local-position drop (FM-6).

AC-15c **[corrected 2026-09-11]**: the paragraph below originally read that PX4 had rejected the
in-flight re-registration because `Mode 'Guara CF Gateway' already registered` appeared in `px4.log`.
That is wrong. PX4 prints that warning on the *accept* path of `Modes::addExternalMode`
(`ModeManagement.cpp:137`) and the run had `COM_MODE_ARM_CHK = 1`, the SITL override of the firmware
default, so the armed registration **succeeded** — `guara_rta_node_restart.log` of run
`20260911T190155Z_restart_arbiter_armed_s42` shows `registered ... (executor id 2, nav_state 24)`.
See `docs/reviews/2026-09-11-m1-m5-review.md` finding C-1.

The criterion was re-run after the fix, with `COM_MODE_ARM_CHK` pinned to 0 and recorded in the run
contract (run `20260911T222015Z_restart_arbiter_armed_s42`): `px4.log` carries
`Not accepting registration requests while armed` (`ModeManagement.cpp:378`) while airborne, the
restarted arbiter aborts with `registration of executor and owned mode failed`, and
`check_ac.py AC-15c` passes. After landing, `doRegister` succeeds again, which is allowed once
disarmed (G 2.7).

Hang and drop injection compile only with `-DGUARA_SIM_FAULT_INJECTION=ON` and trigger
that many seconds after the first CF sample. FM-4 hangs the decision callback group
(arming checks keep running and report a stalled heartbeat). FM-5 hangs the default
group (PX4 sees no arming-check replies). FM-6 ignores `vehicle_local_position` so `V(k)`
trips HOLD.

## Open risks

- Registration (`doRegister`) blocks until PX4 answers; the node cannot be smoke-tested
  without SITL.
- Acknowledgement matching does not carry the requested `nav_state` (comment in `arbiter_node.cpp`).
- Fault-injection compile flag `GUARA_SIM_FAULT_INJECTION` is off by default; SITL FM-4/5/6
  need an explicit rebuild.
- Required local-position age `0.2 s` can trip `T3` during CF if DDS samples stall (seen in AC-14).
