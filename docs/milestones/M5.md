# M5 report — DAIDALUS node (NOSA isolation)

Date: 2026-09-11 · SPEC ACs: AC-10, AC-11 · Grounding: Q5, A.12, A.14 · ADR 0003

## Plan (as executed)

1. Package `nosa/guara_daidalus` links the pinned DAIDALUS tree
   (`third_party/daidalus` tag `DAIDALUSv2.0.3a`, commit `0647596edb218f8e8c7731ff800396297bbace99`)
   without copying or patching those sources (`CHANGES.md`).
2. Wrapper `Evaluator` calls `set_DO_365B()`, `setOwnshipState`, `addTrafficState`, and
   `timeToCorrectiveVolume` [G 5.1–5.4, 5.7, A.14]. Public ROS interface is only
   `guara_msgs/DaaStatus` on `/guara/daa/status`.
3. Node subscribes to `vehicle_global_position`, `vehicle_local_position_v1`, and
   `transponder_report` with `SensorDataQoS`.
4. Default colcon base-paths still omit `nosa/`; `./scripts/daa.sh` builds and tests the
   package explicitly so the rest of Guará remains NOSA-free at build time.

AC-10 uses the recorded ownship/intruder geometry from `C++/examples/DaidalusExample.cpp`
at the pinned commit. The wrapper path converts SI / `TransponderReport` units into the
DAIDALUS `makeLatLonAlt` / `makeTrkGsVs` constructors; the standalone path uses those
constructors directly. Both must agree within ±0.1 s. The node test publishes the same
recorded PX4 messages and checks `/guara/daa/status`.

DO-365B well-clear thresholds remain [HYPOTHESIS] for small civil drones (SPEC R-5, [G 5.8]).
This milestone uses programmatic `set_DO_365B()` (with SUM) and does not introduce a custom
`.conf`.

## Isolation

- `LICENSE` / `LICENSE.pdf` are NOSA 1.3 (copy of `DAIDALUS2-NOSA.pdf`).
- NASA copyright notice is in `nosa/guara_daidalus/README.md`. No project text implies NASA
  endorsement (NOSA 3.E).
- `guara-dev:m1` does not bake DAIDALUS into the image; sources are bind-mounted from
  `third_party/`. Binary/container distribution still needs human legal review (SPEC R-9).
