1 · ASTM F3269 roles → Guará components

ASTM F3269 is the practice defined for bounding unassured functions, artificial intelligence and machine learning included. Guará realises its roles as separate processes so that the assured portion remains small enough to review.

Caveat

The ASTM F3269 text is not available to this project. The mapping below uses the published component names and is marked [REVIEW] until someone checks it against the licensed standard — that review is an open ask.

Mapping of ASTM F3269 architectural roles onto Guará components and packages. Marked [REVIEW] pending check against the licensed standard.

F3269 roleGuará realisationPackage
Complex Function External node publishing guara_msgs/CfSetpoint; reaches PX4 only through the owned mode GuaraCfGateway out of tree
Recovery Function PX4 internal modes Hold / RTL / Land, triggered by scheduleMode PX4
Safety Monitor Copilot monitors, geofence predictor and DAIDALUS node, each publishing a timestamped verdict guara_monitors, guara_geofence, guara_daidalus
Switching Logic DecisionCore — pure, allocation-free, fixed period T_s guara_rta
Input Manager Age and validity checks on every input; the gateway that blocks the CF outside state CF guara_rta
Final layer PX4 internal failsafes and geofence, left enabled PX4

The final row is significant. Guará is not the last line of defence and is not designed to be: the platform failsafes remain enabled beneath it, and Guará never defers one.

2 · The switching core

At each tick k of period T_s the core evaluates four signals: time to loss of well-clear T_daa, time to geofence violation T_gf, the monitor flag M, and the input-validity flag V. Two predicates come out of them.

U(k) = [T_daa ≤ τ_daa] ∨ [T_gf ≤ τ_gf] ∨ M(k) ∨ V(k) unsafe C(k) = [T_daa > τ_daa + h_daa] ∧ [T_gf > τ_gf + h_gf] ∧ ¬M(k) ∧ ¬V(k) clear

U switches to the recovery function in the same tick. C alone does not switch back: the return demands C held continuously for the dwell time T_d, a minimum dwell in recovery, and a switch budget that latches the recovery after N_max switches in a window W. That asymmetry is a design obligation, not an accident.

2.2 · Design obligation O-1

O-1 τ_gf ≥ δ_lat τ_daa ≥ τ_rec,daa + δ_lat

δ_lat is the measured p99 latency from the sample that makes U true to the recovery mode being effective. A trigger threshold shorter than the time it takes to act is a threshold that does nothing. This is why the whole project refuses to publish a threshold without publishing the batch behind it — δ_lat is measured at 61 ms against τ_gf = 1000 ms.

2.3 · Properties of the core

No ROS, no allocation after construction, and a bounded number of operations per tick — the only loop iterates a fixed-capacity history of switch instants. Those three properties are acceptance criteria AC-4, AC-5 and AC-6, which is what lets the core be unit-tested exhaustively without a simulator.

ros2_ws/src/guara_rta/include/guara_rta/decision_core.hpp
// Signals of SPEC §3.1 sampled at tick k.
struct Inputs
{
  double t_s{0.0};                  // t_k, monotonic
  bool in_charge{false};            // IC(k)
  bool owned_mode_active{false};    // the owned (CF gateway) mode is the active PX4 mode
  double t_daa_s{std::numeric_limits<double>::infinity()};  // T_daa(k); +inf = no conflict
  double t_gf_s{std::numeric_limits<double>::infinity()};   // T_gf(k); +inf = no violation
  bool monitor_violation{false};    // M(k)
  Recovery monitor_action{Recovery::kHold};  // highest-rank action among violating monitors
  bool input_invalid{false};        // V(k)
  // Shadow check of the setpoint the CF is currently proposing. It withholds the return T5
  // while the CF still intends to re-enter the unsafe set; it is never by itself a reason to
  // leave CF, because in CF the gateway already filters the setpoint.
  bool cf_intent_unsafe{false};
};

class DecisionCore
{
public:
  // Precondition: validate(parameters) == nullptr. Violations are reported by valid().
  explicit DecisionCore(const Parameters & parameters) noexcept;

  // Evaluates the transition table of SPEC §3.5 for tick k. Inputs with a non-finite or
  // non-increasing t_s, and NaN time signals, are treated as invalid inputs (cause::kInput).
  Output step(const Inputs & in) noexcept;

  // Forces a latched recovery, used when the actuator exhausts its retry budget (SPEC FM-7).
  Output latchOnActuationFailure(double t_s) noexcept;
};

cf_intent_unsafe is the field that bears on an adversarial complex function: one that has just been cut off may immediately re-propose the same unsafe motion. The shadow check runs the geofence predictor on the velocity the CF is proposing, and withholds the return until the planner’s own intent is clear. It is never sufficient on its own to leave CF, because inside CF the gateway already filters the setpoint.

2.4 · Parameters and their status

guara_rta::Parameters — defaults
struct Parameters
{
  double tau_daa_s{30.0};      // DAA trigger threshold
  double tau_gf_s{1.0};        // geofence trigger threshold
  double h_daa_s{5.0};         // additive DAA hysteresis on return
  double h_gf_s{1.0};          // additive geofence hysteresis on return
  double dwell_s{5.0};         // T_d: minimum dwell in RF and minimum continuous clear time
  std::uint16_t n_max{3};      // N_max: CF->RF switches in window W that latch the recovery
  double window_s{120.0};      // W
  bool return_enabled{true};   // enables the T5 return
  bool escalation_enabled{false};  // persistence escalation
  double escalation_s{30.0};   // T_esc
};

Every value above is labelled in the source as a hypothesis to be measured, not a tuned result. validate() returns a static description of the first violated constraint rather than a bool, so a misconfiguration names itself in the log.

3 · States and transitions

Four states, with the recovery function r ∈ {HOLD, RTL, LAND} ranked so that escalation is always permitted and de-escalation never is. Red edges are immediate; green dashed edges must be earned.

The human always wins

Any RC or GCS mode change, and any PX4 failsafe, drops Guará to INACTIVE at once. Guará never defers a PX4 failsafe and never argues with the pilot. This is a rule about who owns the aircraft, not a fallback.

Latching is a feature

A planner that trips the boundary three times in two minutes is not having bad luck. After N_max switches in the window W, the recovery latches and the planner does not get the aircraft back. The switch history survives deactivation, so toggling modes cannot reset the budget.

The full transition table T1–T7, the six required properties P-1…P-6 and every design obligation are in docs/SPEC.md §3; the rationale for returning only from Hold is ADR 0005.

4 · The gateway contract

The switching core decides who flies. The gateway decides what the untrusted side is even allowed to ask for while it is flying. This is where a language model is actually contained, and every row below has a test that fails without it.

Threats posed by an unassured complex function, the gateway enforcement applied to each, and the test that exercises it.

Threat from an untrusted plannerEnforcementTest
The planner stalls and a stale setpoint keeps flying Freshness measured from reception on the gateway clock; implausible stamps rejected test_gateway_envelope.cpp
Confident but out-of-envelope command (speed, climb, yaw step) Clamp to gateway.max_*; non-finite values rejected outright test_gateway_envelope.cpp
A plausible command that flies straight at the fence Shadow check of the proposed velocity against the predictor before forwarding test_gateway_envelope.cpp, AC-9
Unsafe motion re-proposed immediately after a recovery The return requires the CF’s own intent to be clear test_return_policy.cpp
Anti-chattering budget reset by toggling modes Switch history survives deactivation test_return_policy.cpp
Silent death of a monitor or the DAA node Enabled channels fail closed; undeclared omissions refused at startup test_channel_gating.cpp
Structurally malformed or extreme input Property test against an adversarial complex function test_gateway_fuzz.cpp

Freshness is measured on the receiver’s clock rather than from the sender’s stamp. A compromised or malfunctioning complex function controls its own timestamps; it does not control when packets arrive.

The same seven rules in the space domain, on F´ signals instead of PX4 ones (ADR 0015).

The contract above is air-shaped throughout: it names PX4 parameters as the clamp source and the geofence braking model as the shadow check. ADR 0015 restates the same seven rules for the space host, in the same order, so the two read by diff. Its predicate is implemented host-free in space/gateway.py and each rule is the sole refuser of at least one crafted proposal (AC-102, test_space_gateway.py). Two rules deliberately do not transfer: rule 4’s envelope has no authoritative source, because PX4 parameters have no F´ analogue, so it is a declaration marked [PARAMETER TBD]; and rule 5 refuses a slew whole rather than clamping it, because a half-executed slew is not a smaller slew.

Nothing in F´’s command path authorises anything — Svc::CmdDispatcher decodes an opcode and dispatches it — and a default uplink runs ClearTextDecryptor, which authenticates nothing. A space run therefore has to declare which security association and decryptor it used, and a run claiming an authenticated origin its declaration does not support fails the contract check (AC-103). No F´ component exists: what is tested is the decision, on a host, in Python.

Still open before a model drives a CF in anything but simulation

In order: transport authentication on /guara/cf/* and /fmu/in/* (SROS2, failure mode FM-12); a jailbreak corpus against the mission compiler; and the fuzz corpus extended with future stamps and mode-tool abuse.

5 · Channels and fail-closed

A channel is one source of safety evidence. The rule is uniform: an enabled channel that stops producing a fresh verdict is treated as a violation, not as an absence of news. Turning a channel off is possible, but only by declaring the omission — and the flight safety profile refuses to start with an omission that was not declared.

Safety-evidence channels, the signal each produces, the component producing it, and the domain in which it applies.

Monitors carry their own class and their own requested recovery, so the core does not need to know what any individual requirement means — only how authoritative its action is. Recovery actions are ranked HOLD < RTL < LAND, and the core selects the highest rank among violating monitors.

ros2_ws/src/guara_msgs/msg/MonitorVerdict.msg
uint8 CLASS_LOG=0       # recorded only; never enters M(k)
uint8 CLASS_SWITCH=1    # a violation sets M(k) = 1

uint8 ACTION_HOLD=0     # recovery requested on violation; ranked HOLD < RTL < LAND
uint8 ACTION_RTL=1
uint8 ACTION_LAND=2

string monitor_id       # requirement identifier, e.g. REQ-ALT-01
bool violated           # true if the monitored property is violated at this step
bool inputs_complete    # a monitor that has not yet seen all inputs reports false, false
float64 processing_s    # verdict latency, stage L2 of the budget

inputs_complete is what stops a monitor from being quietly useless at startup: a monitor that has not yet observed every one of its inputs reports violated = false and reports the distinction, so the Input Manager can separate “no violation” from “no opinion yet”.

6 · The latency budget

δ_lat is not one number that someone timed. It is a sum of named stages, each measured on a clock that has been validated for that stage, which is what makes it possible to say which stage is excluded and why.

L0PX4 sensor sample → PX4 publish (timestamp − timestamp_sample)p99 0.0028 s
L1PX4 → ROS transport across the uXRCE-DDS bridge — excluded, mixed clocksrecorded, not cited
L2Monitor processing, input reception → verdict publishp99 0.0000 s *
L3Verdict stamp → arbiter receptionp99 0.0013 s
L4Arbiter reception → decision tick that sets U(k)p99 0.0249 s
L5Decision → VehicleCommand publishedp99 0.0314 s
L6Command → recovery mode effective in PX4p99 0.0120 s
* Read this before quoting 61 ms

L2 is zero because the latency_hold scenario injects the monitor verdict, so no Copilot evaluation happens on that path. δ_lat is therefore optimistic by construction, and the project records the qualification alongside the value. L1 is excluded because the PX4 and ROS clocks differ by seconds on this SIH/uXRCE setup — a criterion (AC-19) gates any cross-process number until alignment is under 10 ms.

Each RtaEvent carries every one of those instants on a named clock, which is how the aggregation script re-derives the stages rather than trusting a summary:

guara_msgs/RtaEvent.msg — the timing fields
float64 t_decide_s          # tick instant t_k (arbiter steady clock)
float64 t_input_recv_s      # reception of the most recent input that made U true (steady)
float64 t_input_stamp_s     # PX4 timestamp_sample [s] of the last local_position
float64 t_cmd_pub_s         # VehicleCommand publish (steady clock)
float64 t_ack_s             # last SET_NAV_STATE ACK (steady clock)
float64 l0_s                # timestamp - timestamp_sample (PX4 clock)
float64 clock_err_s         # ROS recv - PX4 timestamp (gated by AC-19)
float64 l2_s                # last monitor processing_s
float64 l3_s                # arbiter ROS recv - verdict stamp

Both a steady-clock and a ROS-clock instant are recorded for the same event. That redundancy surfaced the 4.9 s clock misalignment rather than absorbing it into a plausible total. The full batch and how to re-run it →

7 · Message contracts

Five message types are the entire public surface between Guará and anything else. If you are writing a complex function, you need exactly one of them.

The five message contracts forming the public interface of Guará, with direction of flow and purpose.

TypeDirectionPurpose
CfSetpointCF → gatewayThe only thing an untrusted planner may publish
MonitorVerdictmonitor → arbiterOne requirement’s verdict at one step
DaaStatusDAA node → arbiterThe single interface between DAIDALUS and the Apache-2.0 code
RtaStatearbiter → worldPeriodic snapshot for observation and logging
RtaEventarbiter → worldOne state transition with every timing instant

What a complex function is allowed to say

ros2_ws/src/guara_msgs/msg/CfSetpoint.msg
# Generation time of the setpoint on the CF clock. Setpoints stamped before the most recent
# RF -> CF return instant are discarded by the gateway.
builtin_interfaces/Time stamp

# Commanded velocity in the local NED frame [m/s].
float32[3] velocity_ned_m_s

# Commanded yaw in the NED frame [rad]; NaN leaves yaw uncontrolled.
float32 yaw_ned_rad

Three fields. No mode, no arm, no waypoint, no mission upload, no parameter write, no MAVLink. A complex function cannot request a mode change because there is nowhere in the type to put one. This is the same closure principle the Mission Intent schema applies one layer up, and it is why “the model tried to disable the geofence” is not a failure mode that exists here.

What the arbiter tells you about the planner it is watching

RtaState publishes counters that make an untrusted planner’s behaviour observable rather than anecdotal — how often it was clamped, how often it was blocked at the fence, how often it sent something implausible:

guara_msgs/RtaState.msg — the CF observability fields
bool     cf_intent_unsafe        # the CF's proposed setpoint would violate the fence
float64  cf_intent_t_gf_s        # T_gf predicted on the CF's proposed velocity
uint32   cf_rejected_stamp       # setpoints rejected for an implausible stamp
uint32   cf_rejected_non_finite
uint32   cf_rejected_guard       # setpoints blocked by the shadow guard
uint32   cf_clamped              # setpoints clamped to the gateway envelope
uint32   invalid_mask            # which channels set V(k) at this tick
uint32   accepted_omissions      # declared protection omissions (1=daa, 2=monitors, 4=geofence)
bool     actuation_failed        # a mode request was not accepted, or accepted without effect

cf_clamped is the metric to watch when you swap in a new model. A planner whose commands are constantly being clamped is not being contained successfully — it is being contained repeatedly, which is a different and worse thing.

8 · What changes in orbit

The decision core is unchanged. The signals are replaced wholesale, because the physics is different and because pretending otherwise is how ported safety logic goes wrong.

What survives the move

  • U / C predicates and the four states
  • Asymmetry: leave immediately, return slowly
  • Fail-closed channels and declared omissions
  • The closed intent vocabulary, one layer up
  • The arbiter, now an FPP component on a rate group

What does not

  • No DAA channel, ever. Conjunction assessment is a ground-based probabilistic process
  • The geofence braking model — an orbiting body cannot stop
  • The recovery function itself: F´ has no safe mode
  • Return to the complex function: the space safe mode is latched, released only by ground command

The one space channel that exists as code today is the attitude keep-out predictor. It answers a purely geometric question — at the current attitude and body rate, when does a protected boresight enter a keep-out cone around a bright body — and it answers it in closed form rather than by numerical integration, so its tests can demand ±0.05 s the way the geofence predictor’s do.

space/keepout.py
"""Attitude keep-out predictor (ADR 0012 channel `attitude_keepout`, AC-47).

An orbiting body cannot stop, so the air geofence's braking model does not transfer.
This predictor answers a purely geometric question: at the current attitude and body
rate, when does a protected boresight enter a keep-out cone around a bright body?

Fail-closed: non-finite inputs, a zero-length vector, or an already-violated cone
report T = 0. Receding, still, or out-of-horizon cases report +inf.
"""
TOL_S = 0.05  # AC-47 tolerance; documented here so tests and callers share it.
Risk RS-1 — attack this first

The space recovery function does not exist in F´ and must be written by this project. A safe mode with no flight heritage is the single largest weakness in the orbital thread, and the project would rather have it reviewed early than discovered late. It is an open ask.
